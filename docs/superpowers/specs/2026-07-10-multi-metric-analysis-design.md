# 多指標 地域分析ツール 設計（ポートフォリオ強化）

**Goal:** estat-aging-dashboard を「高齢化率を地図で見るだけ」のビューアから、**複数の指標を合成した『課題スコア』で自治体をランキングし、支援が必要なターゲット地域を発見できる分析ツール**へ進化させる。地域分析／GIS 領域で「意思決定を助けるツールを作れる」ことを示すポートフォリオにする。

**進め方:** これはコーチング用の設計書。実装は jun 本人が行う（ヒントとレビューで伴走）。実装計画は別途ランブックとして作成する。

---

## プロダクト概要

- **5指標**: 高齢化率（既存）／人口増減率／財政力指数／生産年齢人口比率／1人あたり課税対象所得
- ユーザーが **スライダーで重みを調整** できる加重合成「**課題スコア**」（高いほど課題が大きい）
- 課題スコアで自治体を **ランキング** ＋ 地図でハイライト
- ランキングを **Excel(.xlsx) 出力**
- 地図の見た目（凡例・ツールチップ・配色）を改善

## 方針・制約

- **作り方: データ先行** — 多指標のデータモデル＋ETLを先に作り込み、その後に分析UI。
- **最初にフィージビリティ・スパイク** — 各指標が市区町村レベルで取得でき、`area_code` で結合できるかを1件ずつ検証してから作り込む（データ先行の最大リスク＝途中で「取れない」と判明、を先回りで潰す）。
- コーチング方針: jun 本人が実装（コード丸写しはしない）。
- コスト: 既存の無料／低コスト構成の範囲内。

## 設計

### ① データモデル（ロング形式で N 指標対応）

現状 `Municipality(code, name, pref, aging_rate, geom)` は `aging_rate` を列にハードコードしており、指標追加のたびに列追加＝拡張しづらい。

新モデル（ロング形式）:

- **`Metric`** — 指標の**定義**: `key` / 表示名 / 単位 / 出典 / 年次 / **方向(polarity: 高いほど課題か)** / 正規化情報
- **`MunicipalityMetric`** — 自治体 × 指標 = **値**:
  - `value_raw`（生値）
  - `value_challenge`（課題方向に揃えた正規化値、0〜1で **1 = 最も課題が大きい**）

指標追加＝行を足すだけ（スキーマ変更不要）。既存の高齢化率も新モデルへ移行する。

### ② ETL

- **A. フィージビリティ・スパイク（最初のステップ）**: 各指標の出典・粒度・結合キーを検証。
  - 想定出典: 高齢化率／人口増減率／生産年齢人口比率 = 国勢調査（e-Stat API、既存で使用実績あり）／ 財政力指数・1人あたり課税対象所得 = 総務省系（**要確認**）。
  - 取得不可／結合不可の指標があればこの時点で差し替え判断。モデルがロング形式なので **指標が入れ替わっても設計は無傷**。
- **B. 取り込みコマンドの汎用化**: 既存 `import_aging` を一般化し「1指標分の（取得 → `area_code` 対応 → `MunicipalityMetric` へ upsert）」を共通化。
- **C. 正規化は ETL の後処理で計算・保存**: 指標ごとに全自治体の min/max（必要なら分位）から正規化し、**方向を反転**して `value_challenge` に格納。→ API は正規化済みを返すだけで軽い。データ更新時に再計算。
- **D. 年次を揃える**: `Metric` に年次を記録し、比較の妥当性を確保。

### ③ スコア計算 & API

- **スコアはクライアント側で計算**（スライダーの即応性のため）。API は正規化値を返すだけ。
- 式: `score = Σ(weightᵢ × value_challengeᵢ) / Σweightᵢ`（加重平均、高いほど課題大）。
- 方向は ETL で吸収済み（`value_challenge`）なので、フロントは単純な加重平均でよい。
- **API 2本立て**:

  | エンドポイント | 返すもの | 用途 |
  |---|---|---|
  | `/api/metrics/`（新規） | 指標定義 ＋ 全自治体の `value_challenge`（ジオメトリ無し＝軽い） | スライダー・全国ランキング |
  | `/api/cities/?pref=X`（既存を拡張） | 市区町村ジオメトリ ＋ 各指標値 | 地図をスコアで色分け |

- **役割分担**: 全国比較は **ランキング表**（軽い metrics API）が担い、**地図**は既存の県→市区町村ドリルダウンを流用してスコアで色分け（全国の市区町村ジオメトリ ≈7.6MB を一度に描く重さを回避）。

### ④ フロント UX

既存の `Dashboard` / `PrefMap` / `CityList` を土台に:

- **`WeightSliders`（新規）**: 指標ごとに1本（計5本）。合計を100%に正規化して表示。動かすと即座にスコア再計算。
- **`PrefMap`（拡張）**: 課題スコアで色分け ＋ 凡例 ＋ ホバーツールチップ（自治体名・スコア・主要指標）。
- **`RankingTable`（新規）**: 全国の課題スコア上位N。スコア＋各指標値を表示、ソート可、行クリックで地図ハイライト。スライダー変化で並び替わる。
- **`ExportButton`（新規）**: 現ランキング（自治体・スコア・各指標値・現在の重み）を `.xlsx` で出力。**クライアント側生成**（SheetJS 等）。
- **状態**: `Dashboard` が重み(weights)を `useState` で保持（lifting state up）。スコアは `useMemo` で計算。
- **`computeScore(values, weights)`** を共通関数にし、地図の色分けとランキングで**同じロジックを共有**。
- 配色は実装時に配色ガイド（dataviz）を参照。

### ⑤ エラー処理・エッジケース・検証

- **指標の欠損**: 利用可能な指標だけで **重みを再正規化** してスコアを出す。欠損が多すぎる自治体は「データ不足」としてランキングから **フラグ／除外**（閾値を決める）。
- **正規化の外れ値**: min-max は極端値に弱い → 必要なら **分位(5〜95%)でクリップ**。まずは min-max で可、外れ値感度は要注意点として記録。
- **ジオメトリ欠損**（既知例: 津久見市 geom=null）: 地図には出ないが、ランキングは指標ベースなので出る（地図とランキングの関心を分離した設計が効く）。
- **API 失敗**: 既存の try/catch ＋ console.error パターンを踏襲。
- **検証**:

  | 対象 | 方法 |
  |---|---|
  | ETL | 指標ごとの件数（≈1700自治体×5指標）、既知値のスポットチェック |
  | 正規化 | 各指標で min=0/max=1、方向が正しいか（財政力が高い自治体は課題正規化値が低い） |
  | `computeScore` | **純粋関数 → 単体テスト**（重み＋値 → 期待スコア）。TDD 向き |
  | ランキング | 妥当性（過疎地の自治体が上位に来るか） |
  | Excel 出力 | ファイルを開いて画面のランキングと一致するか |
  | UI 全体 | スライダー変化で地図とランキングが整合して更新されるか（目視） |

## スコープ外（YAGNI）

- 全国市区町村ジオメトリの一括表示（重いので県ドリルダウンで代替）
- 時系列／年次比較（まずは単年次）
- ユーザー認証・保存機能

## 未確定・要検証（フィージビリティ・スパイクで確定する）

- 財政力指数・1人あたり課税対象所得の入手可否・出典・`area_code` との結合キー
- 各指標で使用する年次の確定
- 正規化方式（min-max か分位クリップか）の最終決定

## 実装フェーズ（概略・詳細は実装計画で）

0. フィージビリティ・スパイク（各指標の出典検証）
1. データモデル（`Metric` / `MunicipalityMetric`）＋ 既存高齢化率の移行
2. ETL 汎用化 ＋ 新指標の取り込み ＋ 正規化
3. API（`/api/metrics/` 新設、`/api/cities/` 拡張）
4. フロント（`WeightSliders` / スコア共通関数 / `PrefMap` スコア色分け / `RankingTable` / `ExportButton`）
5. 地図の美化（凡例・ツールチップ・配色）＋ 仕上げ・検証
